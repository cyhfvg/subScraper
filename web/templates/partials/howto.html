How to use this tool

Start here: what it does, what it needs installed, and the order to do things in.

What this is

subScraper is an intranet asset-discovery pipeline. Give it domains, IPs or CIDRs. It brute-forces DNS where needed, port-scans live hosts, enumerates HTTP vhosts, screenshots web apps, and runs nuclei/nikto. There is no internet OSINT and no third-party API keys.

1 · Check your tools

The pipeline shells out to real recon tools. Anything missing is skipped, which is why a scan can look "done" with nothing found.

2 · Launch a scan

  • Go to Launch Scan and enter a domain: example.com.
  • *.example.com scans the whole sub-scope. example.* fans out over the TLDs configured in Settings → Wildcard TLDs.
  • Multiple targets at once: one per line, or comma-separated.
  • A wordlist path turns on DNSx DNS brute-force and ffuf vhost brute-forcing. Leave it blank to skip both.
  • Nikto is slow. Tick skip nikto for a first pass, then re-run the target later without it.

Going faster

Settings → Workers per tool (default 5) controls how many copies of each tool may run at once. httpx, nuclei and nikto also split a batch of hosts across that many processes, so raising it speeds up a single target rather than only helping when several jobs run side by side.

  • Per-tool slots below it stay at 0 to follow that number. Set one only where a tool needs its own limit - a rate-limited API, say.
  • Max concurrent jobs is separate: it controls how many targets run at once, not how many workers each tool gets.
  • Watch System Resources after raising it. Dynamic mode will pull job counts back down if the box struggles.
  • From the command line: python3 main.py --tool-workers 5.

3 · Watch it run

  • Active Jobs shows each pipeline step, its progress and its log. Jobs can be paused, resumed, or have a stuck step skipped.
  • Queue holds targets waiting for a free slot. Slot count is Settings → Max running jobs, or turn on dynamic mode to let the box decide.
  • System Resources warns before CPU, memory or disk runs out. If scans crawl, lower the job and worker caps there.
  • Logs is the ground truth for a tool that failed - filter by source to see one tool's output.

4 · Read the results

  • Overview is the summary: counts per target, and the JS Findings card with secrets and hidden endpoints found in JavaScript.
  • Reports drills into one domain: every subdomain, HTTP status, title, tech, nuclei and nikto findings, screenshots and command history. Mark a subdomain interesting or leave a comment and it persists.
  • Gallery is every screenshot, paginated - the fastest way to spot an admin panel.
  • Export as JSON or CSV from Reports, or grab the subdomain list as plain text.

5 · JS findings, and why they matter

The JS scan fetches every JavaScript file it can reach for a target and greps it for three things:

  • Secrets - API keys, tokens and credentials left in front-end bundles. Values are redacted in the UI; the source URL tells you where to look.
  • Endpoints - paths the app calls but nothing links to. These feed straight into manual testing.
  • Parameters - query and body parameter names worth fuzzing.

Turn it off or tune the file limit under Settings → JS scan. Re-run it for one domain from that domain's report page.

Bundled nuclei templates

This repository ships hand-written nuclei templates for CVEs that have no template in the official projectdiscovery/nuclei-templates repo. They live in nuclei-templates/ and run in addition to the official set on every nuclei step.

Turn them off under Settings → Use bundled nuclei templates. They are skipped with a note in the job log if nuclei has not downloaded its official templates yet - run nuclei -update-templates once and they come back.

6 · Keep it running

  • Monitors poll a URL holding a newline-separated target list and launch jobs as new entries appear.
  • Backups run on a schedule and can be restored from Settings. Cleanup trims old scan files so the disk survives.
  • Re-running a target resumes it: finished steps are not repeated.

7 · Drive it from an agent

The /api/agent/* API takes a bug bounty program's full scope, runs recon across it and hands back assets, findings and a ranked attack surface. Authentication is a scoped API key, so an agent can be given read-only access, or access to one program only.

Full reference: AGENT_API.md in the repository. Start with GET /api/agent for the endpoint index.

When something looks wrong

SymptomWhat it usually is
Scan finishes instantly, no subdomainsNo enumeration tool installed. Check the tool list above.
A step is permanently "running"The tool is waiting on something. Open Logs, then skip the step from Active Jobs.
httpx found nothingThe Python package called httpx is on PATH instead of ProjectDiscovery's. Install the right one; this app refuses the wrong binary on purpose.
No screenshotsgowitness needs Chrome or Chromium installed.
Auto-install did nothingSystem package installs need root. Run the command shown above yourself, or start the app as root.
Everything is slowToo many parallel jobs. Lower them in Settings or enable dynamic mode.
